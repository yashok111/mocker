# UI review, 2026-09-05 — six readers over the whole admin UI

Six independent reads after `A20` emptied the `EXEMPT` map: three Opus
agents and three `vcodex` (`gpt-5.6-luna`, effort high), one pair per angle —
(1) contract vs screen, (2) forms and edit paths, (3) navigation and first
run. The vcodex read of angle 1 burned its window spawning sub-audits and
returned no table; it was relaunched with a hard budget (its findings, if
any, are appended at the end). The raw reports are session artifacts; this
file is the deduplicated, ranked record — the count in «readers» is how
many of the five independent reports named the same thing.

Already fixed the same day, before this file (each with a test): the drift
repairs had no confirm (2 readers); the stream edit form's PUT omitted
`listSize`/`delayMs`/`reqSchema`; the transfer panel's copy promised
scenarios in the bundle (the export carries none; the fork does); the
stats strip read the admin feed's registry instead of the mock plane's; the
header's status word came off stale query data; a 401 on either probe
bounced the session.

## Three structural readings

**The first one shipped as `A21` step 5 (2026-09-05): `VariantEditor.tsx`.**
One component over the whole variant — a producer select (generated by the
schema / a pinned body / a file from «Файлы» / a Lua function) whose switch
clears what the server refuses beside the new source, the media type and
JSON body, the file select over `GET .../assets`, the Lua box, a headers
key/value list, the `when[]` rows, and a read-only line for recipes and
`schemaPatch`. `OperationEditor`'s per-status panel and the custom-endpoint
edit form both mount it (each keeps its own test ids through two builder
props); validity travels up through one callback to the owning save button.
That closes G4 (bodyRef), G5 (headers), the schemaPatch badge from the
"deliberate absences" list, and the class B2/B4/B5 belonged to. The create
card keeps its flat fields on purpose: a new endpoint is one status and one
body, and the editor is for what already exists.

- **One `VariantEditor`** (all three Opus reads, independently). The variant
  — `{mode, body, bodyRef, function, schema, schemaPatch, recipes, headers,
  when[], mediaType, bodyEncoding}` — is the product's unit of authoring and
  is rendered by two divergent partial forms, each showing four or five of
  the eleven fields; that is why A18 reached one form and not the other,
  and why `headers` reached neither. One component over the whole schema,
  with the exclusivity rules (function ⊻ body ⊻ bodyRef) as unreachable
  states, mounted by both screens, closes B2, B4, B5, G4, G5, G9 and G11 at
  once and turns "does the screen know the new field" into a type error.
- **A dashboard overview with a context bar** (vcodex 3, Opus 3). Spec,
  scenario, directives, drift, traffic in one strip, one primary action
  («Подключить фронтенд» / «Привязать спеку» / «Проверить спеку»), settings
  and transfer below; the same strip reachable from every tab.
- **Read → change → preflight → write** (vcodex 2). Every editor exposes the
  whole document it replaces, marks preserved-but-uneditable fields, and
  attaches server refusals to fields. The same idea as the first, said for
  settings, streams and resources too.
