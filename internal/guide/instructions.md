mocker supports OpenAPI mocks, API design, saved sequences, and backend projects with source-backed graph imports, same-provider reconciliation and pinned revision comparison. This MCP endpoint exposes the same admin handlers as the human panel. A WORKSPACE serves an imported OpenAPI spec on its own host with generated responses and recorded traffic.

First classify the request: mock response configuration, API design, saved sequence, backend project preparation, or source import/reimport/comparison. Read `get_guide {topic:"overview"}` for routing. Mock tasks begin with `get_server_config` → `list_workspaces` → `get_workspace` → `find_operations`; API design and saved sequences read `get_guide {topic:"design"}`. Backend tasks call `get_backend_capabilities`, select a compatible workflow/schema/features, and read `get_guide {topic:selectedWorkflow.entrypoint,guideSetId:selectedWorkflow.guideSetId}`, pinned to its advertised set before mutations. Project preparation uses backend-overview; source tasks use backend-import and its progressively loaded pinned references. Without a compatible workflow remain read-only. Source imports support foundation-graph-v1: initial imports and explicit same-provider reconcile with identity mapping, stale retention and safe deletion. Comparison pins two exact revisions and describes structural changes. SQL/ER, endpoint-flow, proposals, rebase and impact are unavailable.

Four layers decide a response, each over the previous: Spec (never mutated) → Workspace (overrides `set_operation_variant`, custom endpoints `create_endpoint`, settings — persisted, checkpointed) → Scenario (a named snapshot, switched by name) → Session (`set_session_directive`: force a status, fail N times, delay, pause — RAM only, never versioned). A confirmed resource family (`decide_resource`) makes GET/POST/DELETE on `/things` and `/things/{id}` read and write real rows; `set_resource_entity` writes one from your side.

Rules a first call gets wrong: whole-object writes REPLACE (resend everything); `editVersion` is compare-and-swap from the matching read, a stale one returns a `conflict` field with the current document; `confirmSlug` is the workspace's exact slug, read live, on every destructive tool; `opKey` is already percent-encoded, pass it back verbatim; session directives never bump `revision`, so a forgotten one is the usual "the mock is broken". Verify on the mock plane (`probe_workspace`, then `list_traffic`), not by re-reading configuration. No spec yet: `import_spec {name, document}` takes the file's text, JSON or YAML. A configured workspace travels as one document: `export_workspace` → `import_workspace` (spec found by hash or inlined with `includeSpec`), or `fork_workspace` for a copy inside the same installation. Classic workspace API design uses inline response schemas and `export_openapi`; see the design guide.

For analyst API authoring use `list_api_designs` → `get_api_design` → `save_api_design_draft` with the exact `expectedVersion`. Full OpenAPI documents have immutable history, structural diff and separate draft/published mock URLs. `request_api_design_review` returns a human review link; only the analyst UI can publish. Managed workspaces reject legacy mutation tools. `get_guide {topic: "design"}` covers this workflow and the classic workspace approach.

For sequence-canvas scenarios use `list_design_scenarios` → `get_design_scenario`. `run_design_scenario {scenarioId, revisionId, runId, variables?, name?}` starts a complete saved sequence asynchronously; poll `get_design_scenario_run` until `status` is passed, failed or cancelled, then inspect every failed step's request, response and assertions. A successful start is not a passed run. Variable overrides do not change the document. Use a fresh runId for each experiment; after a lost response read the known ID before retrying. `list_design_scenario_runs` and `cancel_design_scenario_run` manage persisted results also visible in the UI. `get_guide {topic: "design"}` has the complete workflow.
