# Immutable observations (verify3)

Negotiate backend-observations-v1 and backend-correlation-v1 with get_backend_capabilities. An old server without these capabilities cannot accept these requests. Do not call a collector, URL or test through adapt.

1. Obtain an already-produced OTLP JSON, JUnit XML or exact Orders terminal report. Declare the complete producer, known/unknown source, environment, UTC window, configurationHash, input, sampling and instrumentation context. Unknown build is explicit; a service name is not source compatibility. Nanoseconds, durations and counters are decimal strings (0..MaxInt64). Probability and JUnit time are plain decimal strings (digits and one optional point; no 0x/0b/0o, underscores or exponents). A measurement unit follows its metric: bytes for request_bytes/response_bytes, count for the others. Nullable input size/unit, probability and scenario retain null; other nulls are rejected.
2. Call adapt_backend_observations {projectId, adapter, context, data} using otlp-traces-json-v1 or junit-summary-v1. For orders-replay-result-v1 replace data with replay:{runId,reportHash}; reportHash is SHA256 of UTF-8 "backend-replay-report-v1\n" plus deterministic JSON of the exact saved report. This reads terminal evidence; it does not execute. Source/build pins must match that report. Review excluded/unsupported/gaps and every explicit resource group. Privacy excludes raw names, SQL, bodies, credentials, exception text and link attributes. Duplicate OTLP links (same trace/span) and self-links are dropped and counted under excluded["links.duplicate/self"]. JUnit names are replaced with digest/ordinal identities; skipped remains skipped. JUnit timestamp is the declared window start, explicitly not measured timing.
3. Save the exact import body and key, then call import_backend_observations {projectId,mode:"create",name,context,batchId,idempotencyKey,records}. Each adapted group is reviewed/imported separately. Keep the returned {setId,version,contentHash,recordCount} receipt.
4. Append using {projectId,mode:"append",setId,expectedVersion,batchId,idempotencyKey,records}. Do not send context/name in append. Identical IDs/content coalesce; changed content for an existing ID conflicts. A successful batch publishes an immutable version even if its content is unchanged.
5. Lost reply: resend exactly the saved body/key. Receipts replay before CAS. Do not issue a new key just because the head advanced.
6. list_backend_observations lists exact versions. Read get_backend_observation_version and get_backend_observation_records with {projectId,observationSetId,version}; records accepts limit/cursor. No latest default. A page cursor belongs to its project/set/version/hash.

Limits: 500 records/1 MiB per import, 4 MiB raw adapter input, 100000 records/128 MiB per set, 256 sets/512 MiB logical project bytes including correlations and version documents, 1000 versions/set, 100 correlations/set, 64 MiB/correlation. No deletion or implicit retention. An over-limit transaction rolls back.

Span links are optional, with missing distinct from []. Up to 32 nonself/nonduplicate links; exact lowercase trace/span IDs. Generic OTLP links are association only. follows_from needs orders-message-causal-v1 and matching receive proof; absent peers remain gaps. B6.1 never turns links into a causal execution sequence. Do not infer causality from timestamps.
